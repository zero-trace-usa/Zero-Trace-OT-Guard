# Zero-Trace OT Guard v1.0.0-rc.6

Engineering prerelease for offline evidence analysis and controlled lab evaluation. Production OT safety and vendor compatibility have not been certified.

## Offline Modbus write detection

- Optional TShark-backed dissection identifies Modbus/TCP write request functions 5, 6, 15, 16, 21, 22 and 23.
- An explicit JSON allowlist permits exact source addresses, optionally restricted to exact destination addresses. Unexpected writes produce Review findings.
- JSON, HTML and CSV reports retain decoded operation, frame/PDU reference, endpoints and authorization outcome. Coverage information includes evaluated rules, processing cap and diagnostics.
- Reply echoes, orphan replies and exception responses are excluded. Multiple Modbus PDUs in a single frame remain distinct.
- Existing CSV and metadata-only PCAP workflows remain available without TShark. Active-check approval requirements and connection controls are unchanged.

## Install and use

Requires Python 3.10 or newer. Install from this tag, not from a similarly named PyPI package:

```sh
git clone --branch v1.0.0-rc.6 --depth 1 https://github.com/zero-trace-usa/Zero-Trace-OT-Guard.git
cd Zero-Trace-OT-Guard
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/python -m otguard --version
.venv/bin/python -m otguard analyze --input examples/sample --output reports
```

Expected version: `Zero-Trace OT Guard 1.0.0rc6`. The CSV sample still produces **3 observed assets, 2 flows and 2 findings**. Windows instructions are in the README; Windows/macOS are not validated in CI.

For optional write detection, install TShark through the operating system's supported package manager and ensure `tshark` is on PATH. Live-capture privileges, API keys and device access are unnecessary. Copy `examples/write-policy.example.json` to a local policy file and replace the documentation addresses with reviewed allowed sources and destinations. Then analyze an evidence directory containing `capture.pcap` without `flows.csv`:

```sh
.venv/bin/python -m otguard analyze --input evidence --output write-reports --write-policy write-policy.json
```

Use `--modbus-tcp-port 1502` only when that is the known Modbus server port. See [write detection instructions](https://github.com/zero-trace-usa/Zero-Trace-OT-Guard/blob/v1.0.0-rc.6/docs/WRITE_DETECTION.md) for policy semantics and supported commands. Verify downloaded packages against the attached `SHA256SUMS`.

## Accuracy and limits

Decoded function fields and MBAP protocol identifier zero are required; a port number alone does not establish a write. Configured server ports still determine request/reply direction. Captured write requests indicate attempted operations, not confirmed device changes. An allowed IP is not an authenticated machine identity.

This release does not assess other industrial protocols, all state-changing Modbus commands, encrypted traffic, or writes hidden by incomplete/undecodable captures. The flow ingestion path still requires classic Ethernet/IPv4 PCAP; PCAPNG and IPv6 captures remain unsupported. No detected writes is not evidence that a capture contains none. Processing/resource limits and dissector coverage can prevent a complete assessment.

## Validation and publication gate

Release publication is gated on Python 3.10–3.13 Linux CI: unit and loopback tests, actual-TShark regression captures, compilation, Bandit, source/wheel builds, source archive resources, existing sample reports and clean installed-wheel Modbus smoke checks. Only the tested Python 3.12 distributions are attached. See [validation status](https://github.com/zero-trace-usa/Zero-Trace-OT-Guard/blob/v1.0.0-rc.6/docs/VALIDATION.md) for local evidence and remaining limitations.

# Zero-Trace OT Guard v1.0.0-rc.3

Engineering prerelease for offline analysis and controlled lab evaluation. Not production-certified or validated for live OT deployment.

## What's new

- Deterministic offline connection plans with reviewed plan identifiers required for execution.
- Signed global connection-attempt rate, per-host cooldown, total attempt budget and consecutive-failure cutoff. Execution remains serial.
- Approval expiry checks during waits and before connections; bounded connection timeouts and cooperative operator stop.
- Durable pre-attempt audit records, run identifiers, timing evidence, planned/actual counts and explicit stop reasons.
- Fail-closed policy validation and regression coverage, including a loopback TCP test that sends no application payload.
- Linux/macOS and Windows setup instructions, operator runbook, multi-version CI and installed-wheel validation.

## Install and run

Requires Python 3.10 or newer. Download the attached wheel and SHA256SUMS. Verify its SHA-256 digest against SHA256SUMS before installation. Checksums detect download corruption; they are not an independent publisher signature.

Linux/macOS:
```sh
python3 -m venv .venv
.venv/bin/python -m pip install ./zero_trace_ot_guard-1.0.0rc3-py3-none-any.whl
.venv/bin/otguard --help
```

Windows PowerShell:
```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\zero_trace_ot_guard-1.0.0rc3-py3-none-any.whl
.\.venv\Scripts\python.exe -m otguard --help
```

For the sample dataset, download and extract GitHub's source archive for this tag, then run from its root:
```sh
.venv/bin/otguard analyze --input examples/sample --output reports
```
Windows users can run the equivalent `.\.venv\Scripts\python.exe -m otguard analyze --input examples/sample --output reports`. Open reports/report.html locally. Expected summary: 3 assets, 2 flows, 2 findings. Offline analysis needs no credentials, service startup, or device access.

## Migration

Active execution now requires `--plan-id` from the current reviewed dry-run. API callers must provide an audit destination; the CLI defaults to active-audit.jsonl. Interrupted execution exits with status 3; invalid input/policy exits with status 2. Existing signed approvals use conservative defaults for the new policy fields. To choose explicit limits, update the approval and re-sign it.

Read docs/SAFETY_ENGINE.md and docs/SECURITY_HARDENING.md before any authorized active use.

## Limits and validation

Connection-attempt limits are not packet-rate limits. OS TCP retransmissions and other network traffic are outside this budget. Budgets apply per invocation and do not coordinate concurrent operators or repeated runs. The shared-key signature and plan identifier do not prove independent human review. Audit logs are not tamper-evident.

Local validation passed 36 tests, compilation, Bandit, package build, clean-wheel installation and offline sample analysis on Python 3.12. This automated release is gated on the same CI checks on Python 3.10, 3.11, 3.12 and 3.13. No hardware-in-the-loop safety assessment, vendor compatibility certification or independent security assessment has been performed.
